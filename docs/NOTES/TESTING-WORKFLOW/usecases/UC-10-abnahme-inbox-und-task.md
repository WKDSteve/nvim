# UC-10 Abnahme-Inbox und Task-Verknüpfung

**Beispiel:** das docmap-Blatt `keyword-card-tab` ist automatisch grün; der Mensch beurteilt nur noch den Screenshot.

## Ziel
Der automatische Teil läuft, der Rest (Urteil, Handschritte) erscheint als Liste; der **Stand** steht in der Live-Check-Task.

## Wann einsetzen
Jede Task mit Live-Check, sobald ein Blatt existiert.

## Wo
- Blatt + `judge`: `docmap.nvim/TESTS/sheets/keyword-card-tab.sheet.lua` (`task = "docmap.nvim/keyword-card-tab-navigation-live-check"`).
- Bericht: `testing sheets report`; Task-Verknüpfung: `--tasks <vault>` (über die Engine von tasks.nvim, nie direkt in die Dateien).
- Referenz: `testing.nvim/docs/SHEETS.md` (Abschnitte *The report*, *Into the tasks*, *One task, now*).

## Voraussetzungen
Ein Lauf mit Ergebnis-IR; für `--tasks` die Engine von tasks.nvim (`$TASKS_NVIM_DIR`, `<vault>/../tasks.nvim`, oder `--tasks-cli`).

## Schritte
1. **Lauf mit IR** (die State-Daten von `scripts/test.sh` sind absichtlich Wegwerf):
   ```bash
   scripts/test.sh --file sheets_spec --json /tmp/docmap-ir.json
   ```
2. **Bericht**:
   ```bash
   testing sheets report . --from /tmp/docmap-ir.json
   ```
   Echte Ausgabe (gekürzt):
   ```
   # Live checks from test sheets
   Generated by `testing sheets report` … from 1 sheet(s): 0 red or not run, 1 to review, 0 manual, 0 automated.
   ## Review inbox (1)
   - [ ] **Keyword card: Tab navigation in a real window** (`keyword-card-tab`, task `docmap.nvim/keyword-card-tab-navigation-live-check`) — `TESTS/sheets/keyword-card-tab.sheet.lua`
     - automated part green; judge:
       - [ ] the keyword card is readable and sits next to its keyword (screenshot card-open)
   ```
   Abschnitte: *Red, stale or not run* · *Review inbox* · *Manual* · *Automated*.
3. **In die Task schreiben** (Block vor `## Notizen`, mit der Zeile `<!-- testing:sheets:states <id>=<zustand> -->`; angehakte Kästchen bleiben angehakt):
   ```bash
   testing sheets report . --from /tmp/docmap-ir.json --tasks E:/repos/tasks-vault [--dry-run]
   ```
4. **Eine Task jetzt** (kein Suite-Lauf): `testing sheets run --task docmap.nvim/keyword-card-tab-navigation-live-check --tasks E:/repos/tasks-vault`
   (läuft nur in vertrauten Wurzeln; ein fehlender Snapshot ist ein Fehler; auf der Workstation verweigert). tasks.nvim: `:Tasks sheet-run`.
5. **Mensch**: Screenshot ansehen (`TESTS/sheets/out/…card-open….png`), Kästchen im Task-Block abhaken; tasks.nvim und tasks-desktop zeigen den Stand.

## Zustände im Task-Block
`green`, `inbox` (wartet auf Urteil), `manual`, `red`, `stale` (Blatt/Spec/Snapshot geändert), `never` (nie gelaufen **oder übersprungen**: kein Browser/Playwright).

## Hinweis zur Prüfung in diesem Verlauf
Schritt 1 und 2 sind so gelaufen (Ausgabe oben echt). Schritt 3 und 4 wurden hier **nicht gegen den Vault ausgeführt**; die Task `docmap.nvim/keyword-card-tab-navigation-live-check` hat
noch keinen Block. Beim ersten Mal mit `--dry-run` beginnen.

## Wenn es nicht läuft
- `task <id> missing`: die Task ist nicht offen/unbekannt; die `task =` im Blatt prüfen (Form `bereich/slug`).
- Kaputte Marker im Task-Block (`begin` ohne `end`): die Task wird **nicht** geschrieben (Exit 1); von Hand reparieren.
- `conflict`: die Task wurde zwischendurch geändert; neu lesen, erneut laufen lassen.
- Ein übersprungenes Blatt steht unter „Red, stale or not run“ als `skip` mit Grund, es macht den Lauf nicht rot (Exit 0).

## Nachmachen
`testing sheets prompt explain` schreibt für einen roten Lauf ein Übergabedokument an eine KI; der Screenshot-Gutachter (ai.nvim) ist eine offene Task
(`testing.nvim/ki-gutachter-screenshots-mit-kriterien-ueber-ai-nvim-bewerte`).
